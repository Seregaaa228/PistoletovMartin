# Скрипты Frontier Nations

`server_scripts/frontier_recipes.js` содержит обычные рецепты, общий тег и
пример производственного шаблона Industry. KubeJS6 и Rhino закреплены отдельно
в `integration-libraries.lock.json`; Architectury9.2.14 уже есть в baseline.

Изменения рецептов, тегов и JSON-шаблонов применяются через `/reload` (нужны
права оператора). `/kubejs reload server_scripts` перезагружает только код и
не заменяет полную загрузку данных. Изменение зависимостей/регистраций требует
перезапуска. В этой интеграции новые registry ID через startup scripts не
добавляются.

Industry читает `data/<namespace>/frontier_industry/production/<name>.json`.
ID шаблона получается из namespace/name. Разрешены четыре factory enum:
`DRONE_FACTORY`, `VEHICLE_FACTORY`, `MISSILE_FACTORY`, `EQUIPMENT_FACTORY`.
Поля: title (1–96 символов), output (item/count), cost (1–12 непустых
item/count), ticks (1–72000), fePerTick (1–128). Count — целое 1–64, не больше
размера стопки предмета. Произвольные NBT/результаты-сущности не принимаются.
`enabled:false` скрывает этот ID для новых неоплаченных единиц; ошибочные
шаблоны отклоняются с ID и причиной в журнале сервера.

Оплата происходит перед каждой единицей, а постановка заявки — раньше.
Оплаченная единица сохраняет output, стоимость, время и FE; изменение/скрытие
шаблона не меняет её после reload или перезапуска. Остаток заявки ещё не оплачен
и использует актуальный шаблон. Старые оплаченные единицы без снимка
восстанавливаются из полного встроенного каталога, включая скрытые старые ID.
Если восстановление невозможно, заказ сохраняется для отмены с возвратом.

На сервере и клиентском тестовом профиле используйте один и тот же набор
скриптов. Принятый 27-JAR профиль остаётся исходной контрольной копией.
