# Диагностика очереди управления авиацией

Диагностика предназначена для отдельных тестовых профилей. По умолчанию она
выключена; она не меняет управление, физику, сетевой протокол или интерфейс.
Включите её свойством JVM `-Dfrontier.flightDiagnostics=true` при запуске
тестового клиента или выделенного тестового сервера. Для обычного лаунчера
передайте свойство среди аргументов JVM, а не игровых аргументов.

Пример для отдельного профиля проекта с ещё не существующим именем:

```sh
python3 tools/create_test_profile.py vendor/flight-controls-work/qa-flight-your-run
JAVA_TOOL_OPTIONS=-Dfrontier.flightDiagnostics=true \
  python3 tools/run_test_client.py vendor/flight-controls-work/qa-flight-your-run
```

Используйте отдельный свежий мир, не личный `.minecraft`. Для отдельного
сервера свойство нужно задать и его процессу; встроенный одиночный сервер
находится в процессе клиента. После сценария выйдите из мира штатно и
дождитесь остановки сервера. Строки `[flight-diagnostics]` появляются в
выводе процесса при закрытии клиентского мира и остановке сервера; при
аварийном завершении невыгруженные значения теряются. `lifecycleEnd=true`
означает только вызов выгрузки, а не успешное завершение сценария.

Серверный агрегат суммирует все управляемые самолёты в процессе сервера:

- `accepted` — принятые серверной очередью кадры; `merged` — сколько из них
  было объединено с уже ожидающим кадром;
- `dequeued` — кадры, извлечённые из очереди перед шагом модели, а не
  подтверждение успешной физики; `empty` — чтения пустой очереди;
- `depth0`–`depth3` — распределение глубины сразу после добавления кадра;
  `depth0` при этом всегда равно нулю.

Клиентский агрегат относится к одному жизненному циклу `ClientLevel` и может
разбиваться при смене измерения:

- `localPredictionSnapshots` — принятые предсказанием локального пилота
  снимки; `pendingSum` и `pendingMax` — сумма и максимум оставшихся после их
  обработки непогашенных кадров;
- `evictedPending` — кадры, вытесненные из ограниченной истории предсказания.

Агрегаты не содержат имён, адресов или команд игрока. Они не измеряют
input-to-photon, ошибку углов, задержку сети или нагрузку на остальные моды;
совпадение периодов клиентского и серверного агрегатов не гарантируется.
Для исследования записывайте сценарий, SHA JAR, частоту кадров, параметры
стенда и интервалы теста отдельно. Проверка одиночной игры не заменяет
выделенный сервер с двумя клиентами, тесты задержки и нагрузку.
