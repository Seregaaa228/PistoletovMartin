# Измерение производительности полёта

Измерения выключены по умолчанию. Для диагностического запуска добавьте
`-Dfrontier.flightPerformance=true` в JVM arguments отдельно у dedicated server
и каждого измеряемого клиента. Итоги печатаются при остановке сервера и при
выгрузке/смене клиентского мира. Резкое завершение процесса теряет ещё не
выведенные данные.

`wholeServerTick` — интервал между обработчиками START и END тика Forge на
серверном потоке. Он включает работу всего сервера и других слушателей событий,
а не только полёт или этот мод. `frameInterval` — интервал между началами двух
подходящих клиентских кадров. Сэмплы собираются только при загруженном мире,
активном окне, отсутствии паузы и экрана и при активном пилоте, управляемом
FlightClient. Пауза, потеря фокуса, экран или отсутствие пилота сбрасывают
предыдущую отметку времени, чтобы интервал не пересекал простой.

Frame interval показывает pacing кадров. Он не измеряет input-to-photon,
длительность рендеринга CPU или GPU, время GPU и задержку сети. Длительности
хранятся в гистограмме фиксированного размера с верхними границами степеней
двух наносекунд. `p50Upper`, `p95Upper` и `p99Upper` округлены к верхней границе
соответствующей корзины; `min` и `max` точные. Сумма насыщается на
`Long.MAX_VALUE`. Серверная метрика объединяет все серверные тики. Клиентская
метрика относится к одному жизненному циклу `ClientLevel`.

Для сопоставимого прогона используйте отдельный свежий тестовый мир, один и тот
же профиль, одинаковые настройки графики и неизменный маршрут. Проведите сначала
контрольный запуск без свойства, затем измерительный с ним. На dedicated server
и обоих клиентах измерительного прогона задайте свойство одинаково. На каждом
сценарии дайте нагрузке стабилизироваться, выполняйте одинаковый манёвр заданное
время, затем штатно выгрузите мир и остановите сервер. Не сравнивайте интервалы
кадров разных машин как абсолютную стоимость рендеринга.

Матрица сценариев: 1, 8 и 16 самолётов; два настоящих клиента; RTT 0, 160 и
300 мс. Для каждого сочетания запишите число самолётов, фактический RTT,
длительность прогона, `wholeServerTick` и `frameInterval` с обеих клиентских
машин. Повторите каждый прогон несколько раз и сохраните сырые строки журналов.
Задавайте RTT одним и тем же контролируемым способом в обоих направлениях;
проверьте фактическую задержку до и после прогона. Контрольный запуск без
свойства нужен для оценки самого эффекта включённого измерителя.

Частичные результаты и воспроизводимые component benchmarks приведены в
[PERFORMANCE-VALIDATION-2026-10-27.md](PERFORMANCE-VALIDATION-2026-10-27.md).
Полная матрица dedicated server / двух клиентов / RTT пока не выполнена.
Компиляция кода сама по себе ничего не говорит о производительности игры.

Для локального интегрированного сервера добавлен отдельный helper JAR:

```sh
GRADLE_USER_HOME="$PWD/vendor/gradle-cache" python3 tools/build.py --offline :aviation:flightPerformanceTestJar
python3 tools/run_flight_performance.py --label after --aviation-jar build/team-mods/frontier-light-aviation-1.1.0.jar
```

Скрипт создаёт собственный свежий профиль, окно Xvfb и мир, запускает реальный
клиент и сохраняет SHA256, серверные и клиентские JSONL, снимки и итоговый JSON.
Измеряются 1/8/16 загруженных соседних F-16, из которых один управляется
пилотом. Это не означает, что все модели одновременно попадают в кадр.
Перед замером выдерживается 10 секунд прогрева, затем 20 секунд измерения
для каждого количества. В конце выполняется обычный взлёт клавишами.
Нужны закреплённый runtime, MC Pilot и Xvfb. Запускайте до/после при одинаковой
внешней нагрузке; параллельная пользовательская игра искажает сравнение.
Helper не входит в releaseJars и в основной профиль не устанавливается.
