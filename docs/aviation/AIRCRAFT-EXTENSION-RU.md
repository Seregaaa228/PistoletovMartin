# Добавление самолётов и подключение пилота NPC

Основа: Minecraft 1.20.1, Forge 47.4.0, Java 17 и закреплённые SBW/DSM.
Точка входа — `modules/aviation/src/main/java/dev/frontier/aviation/aircraft/AircraftCatalog.java`.

## Новая модель

Добавьте `AircraftDefinition` с новым стабильным `frontier_aviation:<id>`.
Определение связывает `FlightProfile`, `HandlingProfile`, `WeaponLoadout`,
`destroyOnDeath` и `AircraftModel`. Ненулевой `AircraftModel` регистрирует
сущность Su24mEntity, предмет развёртывания и стандартный AircraftRenderer.
Для уже зарегистрированной сторонней сущности используйте `model = null`:
каталог тогда описывает возможности и не регистрирует её повторно.
Девять существующих native записей сейчас подключают управление; их loadout
равен `NONE`. API вооружения подключён к трём собственным моделям. Для оружия
другой native сущности нужны явный loadout и совместимый адаптер запуска,
а затем отдельная игровая проверка.

Дублирующий ID или повторяющиеся slot/native gun внутри loadout запрещены.
Существующие ID нельзя переименовывать: они используются сохранениями.
У новой модели нужны собственные ресурсы по примеру F-16:

- `data/frontier_aviation/sbw/vehicles/<id>.json` — native физика и оружие;
- `assets/frontier_aviation/sbw/vehicles/<id>.json` — клиентское описание;
- геометрия `models/bedrock/vehicle/<id>.geo.json`, дальняя модель и анимации;
- текстуры самолёта/предмета, `models/item/<id>.json`, переводы.

Каталог не генерирует геометрию или анимации. Если новой модели нужен иной rig,
добавьте соответствующий клиентский адаптер; не копируйте условия F-16 в сервер
управления. Проверьте точки вращения, шасси, сопла, вид из кабины и дальний LOD.

## Настройка полёта

`FlightProfile` задаёт контур управления и его тайминги. `HandlingProfile` задаёт
небольшое дополнительное демпфирование боковой скорости поверх native engine:

| Поле | Смысл |
| --- | --- |
| `nativeOnly` | Полностью отключает дополнительную поправку |
| `lowSpeedDamping` | Доля боковой скорости, убираемая за тик на малой скорости |
| `highSpeedDamping` | Доля на скорости полной эффективности |
| `fullAuthoritySpeed` | Скорость перехода, блоки/тик; 0 означает полный коэффициент сразу |
| `maximumCorrectionPerTick` | Верхняя граница изменения скорости за тик, блоки/тик |

Коэффициенты демпфирования ограничены [0,1]. Поправка действует только в воздухе,
один раз в native физическом шаге; replay команд повторно её не добавляет.
Тяга, подъёмная сила, падение, столкновения и интегрирование остаются native.
Эта калибровка сама по себе не выполняет автоматический координированный разворот.

## Вооружение и прицел

`WeaponMount` связывает стабильный slot, например `missile`, с точным именем gun
из native JSON, например `Missile`. Здесь задаются вид оружия, предел залпа,
интервал намерений в тиках и максимальная дальность. Боезапас, перегрев, перезарядка,
урон и фактические снаряды принадлежат native SBW/DSM. DSM дополнительно
синхронизирует пушку из собственного `cannonRounds`; не заводите отдельный счётчик.
Новый slot обязан
существовать в weapons пилотского места и иметь соответствующий JSON gun.

Ручной AGM F-16 использует общий с пушкой origin/direction HUD. Сервер проверяет
дальность, сектор и первое препятствие без принудительной загрузки чанков.
Каждая ракета получает направление от собственной подвески к проверенной точке.
Только такой пуск помечается `frontierAircraftDirectAim`; штатный подъём траектории
AGM для него выключен. Остальные AGM сохраняют штатное наведение. Маркер хранится
в обычном persistent NBT; второй набор данных оружия не создаётся.

В закреплённом SBW `AddShooterDeltaMovement` умножает начальную скалярную скорость
ракеты на модуль скорости носителя. Это не сложение векторов. Ручной пуск сохраняет
полученную native скорость с нижней границей базовой скорости ракеты для стоянки.
Не вычитайте вектор скорости самолёта из направления такой ракеты.

Короткий клик выпускает одну ракету при отпускании. Удержание около 300 мс
запрашивает две одновременно; дальнейшее удержание не создаёт бесконечную очередь.
Смена места, lease, оружия или открытие экрана сбрасывают жест. Сервер повторно
проверяет пилота, epoch, выбранный gun и native готовность при выполнении очереди.

Текущий AGM — воздух–земля (`OnlyLockBlock=true`). `fireTracked` предназначен
для будущего loadout с реальным native entity seeking; он не превращает AGM
в ракету воздух–воздух. Ракеты внешних mission/pylon систем DSM требуют своего
адаптера; их нельзя автоматически объявлять GunData slots каталога.

## Цикл NPC

Выполняйте API на серверном потоке. Посадите настоящий `LivingEntity` в пилотское
место, затем получите `AircraftController.acquire(pilot, plane)`. Храните
возвращённый `ControlLease`, а не только UUID самолёта. Каждый серверный тик
подавайте одну команду с возрастающей `sequence`, включая нейтральные тики:

```java
var status = AircraftController.submit(pilot, lease, PilotCommand.neutral(++sequence));
var snapshot = AircraftController.observe(plane);
```

Для манёвров используйте `new PilotCommand(sequence, pitch, yaw, roll, throttle,
brake, secondaryBrake, boost, ignition, gear, hover)`. Оси конечные в [-1,1];
режимы `ModeRequest.ENABLE`, `DISABLE`, `KEEP`. Epoch содержится в lease,
не в PilotCommand. После таймаута, смерти или смены места старую lease не
используйте; при восстановлении места запросите новую. При завершении вызовите
`AircraftController.release`. Не пишите напрямую позицию, yaw, мощность и ammo.

У F-16 ровно два slot ID: `cannon` и `missile`; допустимое количество за намерение
соответственно 1 и 1–2. Это те же строки для `select`, `inspect` и `fire`.
`AircraftArmament.inspect` возвращает rounds, heat, selected и ready. Сначала
выберите оружие и проверьте готовность, затем запросите `fire`.
`QUEUED` не подтверждает выстрел или попадание. Native callback ещё может
отклонить намерение после смены пилота/оружия или изменения готовности.

Пушка закреплена на самолёте. Ненулевой target в `fire` проверяет выравнивание
в пределах 1°, а не поворачивает ствол; сначала доведите самолёт командами.
`InterceptSolver` решает только встречу при постоянных скоростях с ограничением
времени полёта. Его `launchDirection` относится к составляющей скорости до
сложения с унаследованным вектором. Передавайте этот вектор только для оружия,
которое действительно складывает скорости; не учитывайте его дважды. Решение
не включает ускорение AGM, наведение, гравитацию и препятствия. При совпадающих
начальных позициях результат имеет время 0 и нулевое направление — это не
команда нормального пуска.

Обнаружение целей, распознавание своих, выбор цели, заход на атаку, преследование,
уклонение и предотвращение огня по своим относятся к будущему слою поведения.
Общий API и тестовый NPC не являются готовым ИИ воздушного боя.

## Проверка расширения

Чистые тесты каталога и математики подключены к `:aviation:flightChecks`.
Общий маршрут проверки — README. Отдельный opt-in runtime helper собирается
через `:aviation:aircraftSystemsTestJar`; он не входит в production JAR.
`python3 tools/run_aircraft_systems_checks.py` создаёт новый проектный профиль
и свежий мир, запускает native projectiles и сохраняет SHA256 и результаты
в `vendor/aircraft-systems-20261027`. Он не управляет основным клиентом.

Для реального мышиного спуска/ПКМ/G добавьте `--scenarios gesture gear`.
`--baseline-aviation --scenarios seed_wreck` использует проверенный замороженный
JAR `3ff9cca` только в новой тестовой папке. Затем `--resume-profile <эта-папка>
--scenarios restart_wreck --reload` устанавливает текущий JAR в тот же тестовый
профиль и запускает новую JVM. Runner отказывается менять JAR активного своего
клиента; пользовательские профили и скопированные миры не принимаются.

Одиночный запуск не подтверждает dedicated, два клиента, restart, визуальную
работу кабины/шасси или сетевую задержку. Эти сценарии проверяются отдельно.
