# Стабильность управления авиацией: 26 октября 2026

Исправление жалобы на пропадание отклика мыши/A/D с последующим резким поворотом
в одиночном мире. Ветка `codex/flight-controls`, контракт revision 3. Версии
Minecraft 1.20.1 / Forge 47.4.0 / Java 17, зависимости, native ID, старые поля
сохранений и preserved-combat не менялись.

## Воспроизведённые ошибки кода

- История прогноза сравнивала клиентский `environment.tick` с серверным временем.
  При разных часах уже подтверждённый ввод проигрывался повторно: в регрессионном
  примере ожидаемый yaw 1° превращался в 3°. Теперь каждому реальному шагу ввода
  назначается собственный sequence, а ACK удаляет кадры по sequence внутри epoch.
- ACK обновлялся при получении пакета. Теперь отдельно хранятся полученный,
  потреблённый и применённый sequence; только успешный шаг модели подтверждает
  потреблённый кадр. Новый пакет не может попасть в подтверждение предыдущего шага.
- Native render getters используют обычный линейный lerp. При переходе 179° →
  -179° промежуточный угол становился 0°, создавая почти полный обратный оборот.
  Предыдущие yaw/pitch/roll теперь приводятся к ближайшему эквиваленту после
  native-физики; в том же тесте промежуточный угол -180°.
- Replay не учитывал промежуточные native пределы углов. После упора и реверса
  в тесте получалось 57° вместо физически ограниченных 50°. Каждый кадр теперь
  сохраняет и применяет свои пределы pitch/roll; native emergency остаётся свободным.
- Вычитание коррекции после native clamp восстанавливало скрытый недопустимый угол.
  В тесте Tom6 предел +3° превращался во внутренние 18°. Readback теперь сбрасывает
  коррекцию только затронутой оси, сохраняя итоговый native угол.

Клиентский START обновляет намерение управления; одна команда отправляется только
при фактическом шаге физики. Удерживаемые клавиши сохраняются, mode edges не теряются
из-за KEEP и потребляются один раз. Потеря фокуса очищает ожидающий ввод.
Для client dedup используется монотонный счётчик тиков, не изменяемое синхронизацией
время мира. История по-прежнему ограничена 80 кадрами.

C2S теперь идёт до 20 команд/с, включая неизменное удержание; прежний idle heartbeat
5 Гц заменён точным обозначением кадров. S2C сохраняет 10 Гц и переходы состояний.
Wire-структура и ID сообщений прежние, но семантика требует совпадения нового
канала `1.1.0:flight2` на клиенте и сервере.

## Границы проверки

По поручению пользователя выполнена проверка кодом. Реальный одиночный полёт,
мышь/A/D при разном FPS, focus/menu/free look, сервер с двумя клиентами, RTT,

эти изменения по-прежнему могут требовать серверной коррекции. Текущая коррекция
участвует в клиентском native расчёте и затем readback; она не заявляется полностью
изолированным визуальным слоем. Из прохождения тестов не выводится игровая приёмка.
Локальные полные журналы и независимое ревью находятся в игнорируемом
`vendor/flight-controls-work/stability-*`.
